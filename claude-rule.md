# Screen recordings as requests (SRTC)

When a message carries a screen recording (frames, a `watch-record-events` block, a transcript) and the typed text is empty or just a word or two, the spoken narration IS my request.
- Use the frames and the click positions to resolve "this", "here", "that one", "the thing I'm pointing at".
- Carry the request out directly. Ask one question only if it is genuinely ambiguous; otherwise state your assumption in one line and proceed.
- Timestamps in the transcript and frames line up; when I say "first … then …", follow that order.
- If the narration contains several requests, do them in the order spoken and report each in one line.
